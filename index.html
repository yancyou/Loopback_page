Towards a Unified View of Residual Looped Transformers

Loopback in one minute

Why sharing weights leaves update reuse open, three ways a loop can reuse its updates, the Loopback recipe, and the results at four scales.

Performance overview

Loopback trains a looped stack to lower loss than a dense control of the same executed depth, with 40–68% of its Transformer parameters, at every scale we ran.

Abstract

Looped Transformers reduce parameter count by repeatedly applying shared blocks, but parameter sharing alone does not determine how the results of repeated computation are reused. Building on the depth-memory view of residual connections, we analyze how the written representation and weighting rule constrain the contribution of each update. Storing a full block output also writes back its input, changing how earlier information is carried forward. Reading individual updates with a separate input path exposes independent controls over input strength, total update weight, and allocation. Guided by this analysis, we develop the Loopback Transformer, which stores individual block updates and keeps the shared stack's input on a separate path. Geometric decay controls total update weight and supplies a recency prior, while attention learns how to allocate that weight. On ClimbMix, Loopback uses only about 40% and 58% of the dense controls' Transformer parameters at the 191M and 374M scales, respectively, while achieving lower validation loss and better downstream performance at the studied training budgets; the advantage persists at 778M and 1.4B with about two thirds of the parameters. Comparisons use the same training-token budget and computational depth within each scale.

Key contributions

One interface for residual rules

Addition, Attention Residuals, Hyper-Connections, mHC, Hyperloop and recurrent depth readers all write a value, carry old memory forward, and read it to form the next hidden state. Unrolling the interface gives every earlier update an explicit coefficient and exposes two couplings: storing a full block output rewrites the input it contains, and a joint softmax over input and updates ties their weights to a single unit.

Store updates, keep the input on its own path

Loopback appends each block's update rather than its output and keeps the shared stack's input at coefficient one. At every visit end a geometric factor λ shrinks all stored weights, so the prior favors recent visits and the total update weight stays bounded by Kλ/(1−λ).

Attention allocates the total

A destination query scores the normalized updates and redistributes the decay-set total across them. Zero queries recover the decay-only loop exactly; λ = 1 with zero queries recovers ordinary addition. A fused Triton kernel streams the stored updates once per read.

Fewer parameters, lower loss, at four scales

Against dense controls of the same executed depth and token budget, Loopback reaches lower validation loss and higher zero-shot accuracy at 191M, 374M, 778M and 1.4B with 40–68% of their Transformer parameters, and it is the best of nine residual rules on one topology at 191M and 374M. The read adds under 0.1% to forward FLOPs.

Method

From residual addition to a controllable read

Three moves separate the controls that ordinary addition ties together: what is stored, how the input is carried, and how the stored weight is set and allocated.

  1. One interface for residual rules

    Addition, Attention Residuals, Hyper-Connections, mHC, Hyperloop and recurrent depth readers all write a value, carry old memory forward, and read it to form the next hidden state. Unrolling the interface gives every earlier update an explicit coefficient, which exposes two couplings: storing a full block output also rewrites the input it contains, and a joint softmax over the input and the updates ties their weights to a single unit.

  2. Store updates, keep the input on its own path, set the total with decay

    Loopback appends each block's update δ rather than its output and keeps the shared stack's input at coefficient one. At every visit end a geometric factor λ shrinks all stored weights, so the prior favors recent visits and the total update weight stays bounded by Kλ/(1−λ).

  3. Attention allocates the total

    A destination query scores the normalized updates and redistributes the decay-set total across them. Zero queries recover the decay-only loop exactly; λ = 1 with zero queries recovers ordinary addition. A fused Triton kernel streams the stored updates once per read.

Results

Every model trains on ClimbMix at 20 tokens per parameter under a warmup–stable–decay schedule, and every comparison within a scale matches the training-token budget and the executed depth: the looped arms share one topology, Dense keeps the same number of block applications. Validation loss is next-token cross-entropy on a held-out ClimbMix shard packed as in training. Downstream accuracy is zero-shot on thirteen tasks with the lm-evaluation-harness, plus WikiText word perplexity. Transformer parameters exclude embeddings and the vocabulary head; shared weights are counted once.

Efficiency

Compute and efficiency

All models execute the same blocks per token, so the read adds under 0.1% to forward FLOPs. It adds memory traffic, which the fused Triton kernel streams once per read; the KV cache is Dense's, and the stored weights are smaller.

  • <0.1% extra FLOPsthe history read costs +0.08% of Dense's forward FLOPs at 191M and 374M and +0.04% at 778M
  • 33% → 19% step-time overheadwith the fused kernel, from 191M to 778M: 167k vs 222k and 63k vs 75k training tokens per second per GPU
  • 29–44% less weight memorybf16 weights including embeddings: 0.20 vs 0.36 GiB at 191M, 1.87 vs 2.64 GiB at 1.4B
  • Same KV cacheexecuted depth and heads are Dense's, so the cache per 4,096-token sequence matches: 240 MiB at 191M to 800 MiB at 1.4B

Ablations

What the two controls contribute

Decay supplies most of the gain over the plain loop and learned allocation adds a further improvement at both scales. At 191M, uniform allocation at decay's total weight recovers 78% of decay's gain, against 20% for its recency profile at the plain total. The gain over Dense grows under initializations that hurt Dense.
